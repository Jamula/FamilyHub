# Copilot auto-merge reconciliation

The repository-native workflow preserves its existing policy: an explicit, non-dismissed **APPROVED** Copilot review of the exact current head enables the `copilot-review` gate, and all remaining rules/checks still apply. A `COMMENTED` review, even on the exact head, is not approval and leaves the check pending; comments can contain changes requested. It may register squash auto-merge under the owner's configured policy, **only if the separate workflow is enabled and branch protections are correctly enforced**. It never invokes a direct merge operation.

GitHub has rejected `enablePullRequestAutoMerge` for an already clean PR with the exact single `UNPROCESSABLE` message `Pull request Pull request is in clean status`. The reconciliation now rereads the PR state/head, warns that the owner must perform the merge action if it is still the same open non-draft PR, and continues to other PRs. It does not retry that rejection, claim auto-merge was enabled, merge the PR, or weaken any review/check requirement. If the PR changed or closed, it records that observation instead.

Only that exact single-error response is handled this way. Permission failures, multiple/ambiguous errors and unrelated failures remain visible workflow errors. Existing bounded unstable-status retries retain their fresh-head and fresh-review checks. Clean status is not a new approval signal and does not replace checks or user acceptance.

This fixes the per-PR queue failure observed in workflow run 40641765175/job 122661301090. The workflow loads code from its trusted workflow revision; a PR changing this script cannot change the privileged workflow's current behavior before it is reviewed and merged. No workflow rerun, merge, deployment or policy activation is performed by the tests.

## November 2026 gate hardening
The `APPROVED`-only change addresses a policy defect where a `COMMENTED` review could previously pass the synthetic check and register auto-merge even when the comment asked for security changes. Regression tests verify explicit approval succeeds and a current-head changes-recommended comment cannot grant the check. This is source-level hardening only. Repository issue #81 still requires an administrator to add `copilot-review` from GitHub Actions to the **required** branch status checks, retain strict `validate`, and independently test gating. The owner disabled the automatic merge workflow during review publication; this PR does **not** enable it, publish other PRs, merge, deploy or relax any rule.
